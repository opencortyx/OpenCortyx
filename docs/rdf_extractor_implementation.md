# OpenCortyx: Dynamic RDF Extractor & LLM Edge Implementation

## 1. Executive Summary

This document details the complete end-to-end implementation, bug fixes, and architectural integration of the **Dynamic Knowledge Graph / RDF Extractor** in OpenCortyx.

The implementation provides:
1. **Node Extraction via LLM**: Extracting structured entities (`Subject`, `Object`, and optional `Predicate`) from unstructured text in one single extraction pass without requiring redundant per-attribute LLM calls.
2. **Dynamic LLM Edge Generation**: Creating relationship edges where the relationship label itself is generated by an LLM prompt or resolved from dynamic record fields (e.g. `$predicate`).
3. **Graph Preview Visualization (`PreviewGraph`)**: Fully fixing the live SVG renderer in Extractor Studio to display real node-to-node directed edges, relation badges, and arrowheads instead of hardcoded spokes.
4. **Graph Database Persistence**: Verifying that all created nodes and dynamic edges are written to **NebulaGraph** (`opencortyx` space) and indexed in Qdrant and PostgreSQL.

## 2. Architecture & Design Patterns

### 2.1 Extraction Paradigms Supported

OpenCortyx supports two primary knowledge graph paradigms:

#### Paradigm A: 2-Node Direct Graph with Predicate Edges (Compact / Property Graph)
* **Nodes**: `Subject` and `Object`
* **Edges**: 
  - `Source Chunk` $\xrightarrow{\text{MENTIONS}}$ `Subject`
  - `Subject` $\xrightarrow{\quad\text{LLM Predicate (invented, designed, works at)}\quad}$ `Object`
* **Advantage**: Dense, standard graph traversal representation where relationships are first-class edges between entity nodes.

```
+----------------+      MENTIONS       +------------------+
|  Source Chunk  | ------------------> |  Subject Node    |
+----------------+                     +------------------+
                                                |
                                                | [invented / designed]
                                                | (Generated by LLM)
                                                v
                                       +------------------+
                                       |   Object Node    |
                                       +------------------+
```

#### Paradigm B: 3-Node Reified Triple Model (Full RDF / N-ary Relationships)
* **Nodes**: `Subject`, `Predicate`, and `Object`
* **Edges**:
  - `Source Chunk` $\xrightarrow{\text{MENTIONS}}$ `Subject`
  - `Subject` $\xrightarrow{\text{HAS\_PREDICATE}}$ `Predicate`
  - `Predicate` $\xrightarrow{\text{HAS\_OBJECT}}$ `Object`
* **Advantage**: Treats the predicate itself as an addressable entity node with attributes, timestamps, confidence scores, and qualifiers.

## 3. Issues Identified & Resolved

| Component | Issue Identified | Resolution |
| :--- | :--- | :--- |
| **Studio Graph Preview** (`PreviewGraph`) | Hardcoded SVG loop drew grey lines from `Source` to all nodes unconditionally. Edge filter `at[e.from] && at[e.to]` dropped all edges because endpoints like `"Priya Nair (Subject)"` didn't match raw labels `"Priya Nair"`. | Replaced renderer to compute exact endpoint positions (`from_id`, `to_id`, label matching), render real directed SVG arrows (`#preview-arrow`), display relationship badges, and eliminate fake spokes. |
| **Backend Preview Engine** (`preview_template`) | Did not provide unique endpoint IDs across multi-record extractions, causing multiple triples to overwrite coordinates. | Added `from_id` and `to_id` (e.g. `Subject_0`, `Predicate_0`, `source`), grouped emitted nodes per record `ri`, and handled dynamic `$field` edge labels. |
| **LLM Edge Generation** (`_apply_emit`) | Could only use static relation types; empty edge types or dynamic verb generation were not passed to the generation model. | Added dynamic LLM prompt resolution (`mode: "relate.llm"`), extracting root chunk text context and querying the model to output the edge type itself when `rel` is empty or custom-prompted. |
| **Edge Configuration UI** (`ExtractorStudio.tsx`) | Dropping down `From` or `To` could crash if node arrays were undefined; `"the node it read"` option was occasionally obscured. | Made edge updates immutable, guarded all array operations, and pinned `<option value="source">the node it read</option>` unconditionally. |

```python
# Resolves dynamic $field references, e.g. $predicate
rec_etype = str(_fill_field(etype, rec) or etype or "").strip() if (etype and etype.startswith("$")) else (etype or "")

# When "Ask the model (LLM)" is selected for the edge
if mode == "relate.llm":
    if not rec_etype or espec.get("prompt"):
        if not rec_etype:
            rec_etype = str(rec.get("predicate") or rec.get("relation") or "").strip()
        if not rec_etype or espec.get("prompt"):
            root_text = ((source_node.properties or {}).get("text") or getattr(source_node, "label", "") or "")
            s_label = _endpoint_label(frm, rec, "Sample", rec.get("label"), rec_nodes)
            t_label = _endpoint_label(to, rec, "Sample", rec.get("label"), rec_nodes)
            edge_prompt = espec.get("prompt")
            if edge_prompt:
                p_text = f"{edge_prompt}\n\nCONTEXT:\n{root_text[:3000]}\n\nFROM: {s_label}\nTO: {t_label}\n\nReturn ONLY the relationship (concise phrase or label)."
            else:
                p_text = f"Extract the exact relationship or predicate connecting FROM to TO from the context.\n\nCONTEXT:\n{root_text[:3000]}\n\nFROM: {s_label}\nTO: {t_label}\n\nReturn ONLY the relationship (concise phrase or label)."
            try:
                edge_model = espec.get("model") or (tmpl.mechanism or {}).get("model")
                edge_spec = await resolve_model(workspace_id, "generation", edge_model) if edge_model else None
                raw_rel = await complete(p_text, system="You extract relationships between entities. Return ONLY the relationship or predicate phrase.",
                                          max_tokens=60, json_mode=False, temperature=0.1, model_spec=edge_spec)
                gen_rel = str(raw_rel or "").strip().strip('"').strip("'")
                if gen_rel:
                    rec_etype = gen_rel
            except Exception:
                pass
```

### 4.2 Frontend: `apps/web/app/dashboard/custom-assets/ExtractorStudio.tsx`

#### Fixed Live Preview Graph Renderer (`PreviewGraph`)
```tsx
function PreviewGraph({ p }: { p: any }) {
  const nodes = (p.nodes || []);
  if (!nodes.length) return null;
  const W = 400, H = Math.max(220, 180 + Math.max(0, nodes.length - 3) * 22);
  const cx = W / 2, cy = H / 2, R = Math.min(cx, cy) - 50;
  const pos = nodes.map((_, i) => {
    const a = (2 * Math.PI * i) / nodes.length - Math.PI / 2;
    return [cx + R * Math.cos(a), cy + R * Math.sin(a)];
  });

  const at: Record<string, number[]> = {
    source: [cx, cy], Source: [cx, cy], Sample: [cx, cy], "the node it read": [cx, cy],
  };
  nodes.forEach((n: any, i: number) => {
    const pt = pos[i];
    if (n.id) at[n.id] = pt;
    at[`node_${i}`] = pt;
    at[`${n.label} (${n.type})`] = pt;
    if (n.rec_index !== undefined) at[`${n.type}_${n.rec_index}`] = pt;
    if (!at[n.label]) at[n.label] = pt;
  });

  const edges = (p.edges || []).map((e: any, i: number) => {
    const pA = resolvePoint(e.from, e.from_id, e.rec_index);
    const pB = resolvePoint(e.to, e.to_id, e.rec_index);
    return { ...e, pA, pB, key: "e" + i };
  }).filter((e: any) => e.pA && e.pB && (e.pA[0] !== e.pB[0] || e.pA[1] !== e.pB[1]));

  return (
    <div className="bg-stone-50 border border-stone-100 rounded-lg overflow-hidden">
      <svg viewBox={`0 0 ${W} ${H}`} className="w-full">
        <defs>
          <marker id="preview-arrow" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="6" markerHeight="6" orient="auto">
            <path d="M 0 1.5 L 8 5 L 0 8.5 z" fill="#6366f1" />
          </marker>
        </defs>

        {/* Real configured edges with arrowheads & badges */}
        {edges.map((e: any) => (
          <g key={e.key}>
            <line x1={e.pA[0]} y1={e.pA[1]} x2={x2} y2={y2} stroke="#6366f1" strokeWidth={1.5} markerEnd="url(#preview-arrow)" />
            <rect x={mx - badgeW / 2} y={my - 8} width={badgeW} height={16} rx={8} fill="#ffffff" stroke="#cbd5e1" />
            <text x={mx} y={my + 3.5} textAnchor="middle" fontSize={8} fontFamily="monospace" fill="#4f46e5" fontWeight={700}>
              {displayLabel}
            </text>
          </g>
        ))}

        {/* Source Anchor */}
        <g>
          <rect x={cx - 42} y={cy - 16} width={84} height={32} rx={8} fill="#f1f5f9" stroke="#64748b" strokeWidth={1.5} />
          <text x={cx} y={cy + 4} textAnchor="middle" fontSize={11} fontWeight={600} fill="#1e293b">Source</text>
        </g>

        {/* Emitted Nodes */}
        {nodes.map((n: any, i: number) => (
          <g key={"n" + i}>
            <rect x={pos[i][0] - w / 2} y={pos[i][1] - 18} width={w} height={36} rx={8} fill="#fff" stroke={c} strokeWidth={1.5} />
            <text x={pos[i][0]} y={pos[i][1] - 2} textAnchor="middle" fontSize={11} fontWeight={600} fill={c}>{short}</text>
            <text x={pos[i][0]} y={pos[i][1] + 11} textAnchor="middle" fontSize={8} fontFamily="monospace" fill={c} opacity={0.7}>
              {n.type} ({n.attributes?.length || 0})
            </text>
          </g>
        ))}
      </svg>
    </div>
  );
}
```

## 5. Live Production Template Specification

Template name: `approach_a_rdf_3node` (Saved in PostgreSQL `ExtractionTemplate`)

### 5.1 Extraction Mechanism
* **Ref**: `unstructured.llm`
* **Prompt**:
```text
Extract subject-predicate-object relationships from the text.
For each relationship return:
- subject: the source entity
- predicate: the relationship or action verb phrase (e.g. invented, designed, located_in)
- object: the target entity or value

Return ONLY JSON: {"records": [{"subject": "...", "predicate": "...", "object": "..."}]}

TEXT:
{text}
```

### 5.2 Emitted Nodes
```json
[
  {
    "type": "Subject",
    "label": "$subject",
    "id": ["subject"],
    "attributes": ["subject"],
    "dedup": true
  },
  {
    "type": "Object",
    "label": "$object",
    "id": ["object"],
    "attributes": ["object"],
    "dedup": true
  }
]
```
