# OpenCortyx Retrieval — the v2 workflow, end to end

> **Handoff record — 2026-08-27**, written when the product moved onto this engine and the v1
> engine was deleted. Still the best description of what the engine does and what is known to be
> wrong with it. One path in it is stale: `retrieve/planner.py` no longer exists — the contract it
> describes is served by `retrieval/adapter.py`.

Written 2026-08-27, after migrating the product onto `retrieval` and deleting the v1
engine. This is the handoff document: what the engine is, what was measured, what was tried and
rejected, and what is known to be wrong. Everything here is a measurement or a code fact — where
something is an opinion or an untested idea it says so.

---

## 1. Headline numbers

Full LoCoMo suite, 1,540 questions (all 10 conversations, category 5 / adversarial excluded —
the published convention), config `cps 400` + temporal extractor + `--scope` + `entity_facts` +
`evidence_ops`, no cross-encoder:

    turn-identity : 2037/2362 = 86.24%
    PROVENANCE    : 2230/2362 = 94.41%

    Single-Hop    96.20% -> 99.22%
    Temporal      90.40% -> 95.47%
    Multi-Hop     80.43% -> 91.52%
    Open-domain   60.58% -> 84.13%

Re-verified end to end on 2026-08-27 (`bench_tmp/prov_1540_final.json`). Turn-identity is +2.58
over the previous full run while provenance moved +0.21 - the asymmetry is the signature of the
per-conversation collection migration. Scoping at the INDEX keeps cross-conversation candidates
out of the pool entirely rather than filtering them after ranking, so fewer competitors survive
the packing cut. Provenance had no room to move; it is already near the ~97.3% honest ceiling.

**Two different numbers, never merged.** Turn-identity asks "did the labelled gold TURN arrive".
Provenance asks "did the context carry what that turn said, in some form" — a `Fact` or `Claim`
carrying `EXTRACTED_FROM` / `CLAIM_FROM` back to the gold turn counts. Reported side by side
because conflating them credits evidence never delivered, or blames evidence that was.

### Against published systems

MindSchema (arXiv 2608.12428) reports 94.03 overall on LoCoMo; MemMachine 91.69; Mem0 92.5;
MindVanilla (their dense+sparse-only mode) 87.60.

**These are a DIFFERENT RULER.** Theirs is judge-scored ANSWER text with gpt-4.1-mini; ours is
evidence retrieval. An audit of the standard judge found it accepts **62.81% of deliberately
wrong but topically-related answers**, and 6.4% of the LoCoMo answer key is corrupted, capping a
perfect system near 93.6. Do not present 94.20 against 94.03 as a like-for-like win. The honest
comparison needs `benchmarks/eval_answer.py` with a matched generator — never run.

## 2. The pipeline, L0 to L4

```
QUESTION
   │
   ▼ L0  UNDERSTANDING            what the question is, before touching the corpus
   │     vocabulary.py    types that ACTUALLY exist in this corpus (13 node, 66 edge)
   │     intent.py        entity | relationship | temporal | aggregation | semantic
   │     entities.py      MENTIONS by structure (caps, quotes, possessives) - no gazetteer
   │     constraints.py   dates as PREDICATES: reject out-of-range, don't hope ranking sorts it
   │     policy.py        which surfaces to run; the rest SKIPPED with a stated reason
   │     planner.py       strategy weights + hop budget + sub-queries + Cardinality
   │
   ▼ L1  CANDIDATES              8 surfaces, fused by RRF over RANK
   │     node_embedding   dense, 3 query representations (full | concept | entity)
   │     attr_embedding   one vector PER ATTRIBUTE (76,606 surfaces)
   │     bm25             Postgres FTS
   │     entity           resolution: binds a mention to a canonical node
   │     fuzzy            trigram
   │     identifier       exact IDs/codes
   │     metadata         date-range + property filters
   │     ontology         lexical ranked WITHIN implicated types
   │     widen()          if the planned surfaces underfill, run the skipped ones
   │
   ▼ L2  GRAPH                   walk from seeds, keep the ROUTE as evidence
   │     edge_scoring     cosine(relation name, question) x rarity - NO weight table
   │     beam.py          query-directed beam search; paths are first-class results
   │     expansion.py     temporal rejection DURING traversal + node affinity
   │     structural.py    entity_facts: an entity's facts in ONE hop (flag)
   │     evidence_ops.py  assemble -> normalize -> INTERSECT/GROUP -> validate (flag)
   │     scope            drop candidates outside the routed collection
   │
   ▼ L3  RANK                    one weighted score; the cross-encoder is a FEATURE, not a verdict
   │     scale trust: exact 1.00 > binding .95 > cosine .80 > path .60 > rrf .50
   │                  > ratio .45 > constant .30  ("constant" = membership, not relevance)
   │     + connectivity, informative, temporal_fit, absent-is-not-zero
   │     abstain if nothing resembles the question
   │
   ▼ L4  CONTEXT                 maximum EVIDENCE per token, not maximum nodes
         dedupe -> merge equivalents -> per-ROLE floors -> fill budget (8,000 tok)
         paths returned as first-class results
```

### Three commitments that constrain every change

1. **No tables anywhere.** Edge relevance is computed, types are discovered from the corpus. This
   is why it transfers between corpora — and why `NEXT_TURN` can never be walked, since
   "next turn" resembles no content question.
2. **Scores carry their scale.** `Evidence.raw_score` is not comparable across surfaces, so
   fusion works on RANK and L3 trusts by provenance.
3. **Skipping is safe because of `widen()`.** Being wrong about intent costs latency, never the
   answer.

## 3. How the product reaches it

    POST /api/v2/answer   -> retrieve.answer.answer_query
    POST /api/v2/context  -> retrieval.adapter.build_context_v2
    GET  /api/v2/retrievers -> workflow_adapter.SURFACES
    MCP  opencortyx_answer / opencortyx_search -> HTTP POST to the same endpoints
    eval.py -> build_context_v2

`workflow_adapter.build_context_v2` serves v1's exact package contract (`context`, `citations`,
`confidence`, `retrievers`, `stage_trace`, `tokens_used`, `abstained`, `caveats`) from a
`RetrievalResult`, so router / abstain capability / session capture / Chat UI are untouched.

**MCP is a pure HTTP proxy** — no separate retrieval path. It inherits the migration by
construction.

### Options that are NOT honoured (reported, never silently dropped)

`result["unsupported"]` names any of these the caller actually set, and a matching row appears in
the stage trace:

| option | why |
|---|---|
| `retrievers`, `rerank` | v2 selects surfaces per question via `policy`; no per-surface switch |
| `abstain_threshold` | v2 abstains on its own feature gate |
| `as_of`, `as_of_ingest` | bitemporal filtering not implemented |
| `rrf_k`, `decompose`, `fast`, `scope`, `profile` | no v2 equivalent |

This matters because the Chat UI renders checkboxes for `retrievers` / `rerank` and MCP exposes
them as tool arguments. An option accepted and ignored is worse than one refused.

**Also not carried over:** v2 has no query cache, so the Settings toggles for cache TTL/enable
now govern nothing (`runtime_config._apply_side_effects` is an explicit no-op saying so).
`caveats` returns empty — `trust.gather_caveats` expects v1 node objects.

## 4. What actually moved the numbers

Measured on 282 multi-hop questions unless stated. **Every mechanism reasoned into existence
returned ~0; every defect found by measurement moved points.**

| change | kind | effect |
|---|---|---|
| per-conversation collections + routing | protocol/corpus fix | **+1.82 full suite** |
| `FACTS_PER_ENTITY` 40 -> 250 | bug fix | **+0.80** |
| `evidence_ops` (after 3 bug fixes) | mechanism | **+0.68** |
| `entity_facts` + `HAS_FACT` backfill | infrastructure | +0.45 |
| Claim embeddings / `collection_id` / `occurred_on` indexing | reachability repair | large, pre-session |
| `bm25_k=1500` | parameter | +0.34, 4 regressions, 3x slower — not shipped |
| conjunction split in L0 | bug fix | **0.00** — reverted (English-only regex) |
| `hop2_lexical` (2026-08-27) | mechanism | **+0.23** — noise; +2 evidence turns of 884 |
| `adaptive_truncation` (2026-08-28) | mechanism | **-42 prov** at 98/282; saved 69% of tokens |
| `aspect_diversity_on` (2026-08-28) | mechanism | **-0.68 prov@20**, median rank 41 -> 45 |

### The protocol fix, because it is the biggest and least obvious

All ten conversations were ingested into **one collection**, so every query searched all ten.
29% of the packed window held turns from conversations that cannot contain the answer. Every
published LoCoMo number is per-conversation ("top-20 relevant memories retrieved **for each
user**"). We were solving a strictly harder problem and the number was not comparable.

`bench_tmp/collections_per_conversation.py` created `locomo/<dialogue>` and repointed 22,218
nodes. Scoping is now an index filter, not a `dialogue_id` post-filter.

**Routed, not inferred — worth 7 points.** An earlier `entity_scope` flag inferred the
conversation from resolved entities and **regressed 5.2 points**: names recur across
conversations and duplicate `Entity` nodes bound to the wrong one.

## 5. Rejected, with measurements (in `experiments.RETIRED`)

Do not re-propose these from the same intuition.

| flag | result | why it failed |
|---|---|---|
| `prf_set` | **-3.17**, 35 worse | PRF query drift: the feedback query pulls in everything resembling the TOP OF THE FIRST PASS |
| `entity_scope` | **-5.20** | inferred conversation bound to a duplicate entity in the wrong conversation |
| `entity_floor` | +0.23 but turn-identity **-2.6** | reserving budget REALLOCATES: 505 smaller blocks replaced 407 fuller ones. Metric-gaming |
| `digest_sets` + `episode_ctx` | **-8.71** | synthesized list nodes ranked 1,2,3 and scored ZERO — a Digest links to no Turn, so it displaced Facts that earn provenance |
| `neighbor_ctx` | never measurable | its population vanished: finishing claim extraction took coverage to 97.2% and left ZERO dark multi-hop gold turns |
| `query_expansion` | -0.10 at 3.4x cost | Open-domain +1.54, Temporal +0.83, given back elsewhere |
| `multi_query` | not shipped | rephrasings are ABSTRACT ("community service"); evidence is CONCRETE ("toy drive") — no lexical bridge |
| `hop2_lexical` | **+0.23** (272/282 q unchanged) | phrase search on entities the first pass found. Its premise HELD — a phrase cannot drift as `prf_set`'s feedback vector did, and the spans were real (`Samantha`, `Perseid`, `Amy Ellis Nutt`). Verified reaching the packed window (85 blocks over 25 questions), so this is a verdict on the idea. Unable-to-drift is not the same as being evidence: it spent ~3.4 packed blocks per question on topically-adjacent non-evidence |

## 6. Known walls (measured, not speculative)

**Embeddings cannot separate concepts here.** The two facts that ARE the same concept —
`"Jon lost job as a banker"` vs `"Gina lost job at Door Dash"` — score **cosine 0.525**, at p25
of the corpus distribution. An unrelated pair scores 0.521. No threshold exists. This killed
embedding-based normalization outright.

**The packed context is 1.19% evidence.** Of 365 packed blocks per question, 4.3 are gold, using
105 of 7,932 tokens. Adding candidates at that precision buries rather than helps — which is why
six "retrieve more" mechanisms failed.

**The packed window is ordered badly, and no reordering tried has fixed it.** Gold evidence
sits at median packed rank 41 (mean 72, p90 202) of 300-480 blocks. The headline 91.52%
multi-hop provenance is MEMBERSHIP across that whole window; at the top 20 it is 28.39%.
Three mechanisms were measured against that gap this session - `hop2_lexical` (+0.23),
`adaptive_truncation` (-42), `aspect_diversity_on` (-0.68 @20) - and none moved it. NB our
blocks are ~20-token units, so top-20 BLOCKS is not the published protocol's top-20
"memories"; this is an internal diagnostic, not a restatement against published numbers.

**77% of missed evidence is retrieved, at median pool rank 579 of 1,072.** Ranking interventions
move answers a few positions, never five hundred.

**Intersection questions need an OPERATION, not ranking.** "What do Jon and Gina both have in
common?" has all four gold Facts present and correctly linked, and scored 0/4. `evidence_ops`
addresses this; its concept-SELECTION step is still weak (rarity picks `agrees`/`admires`, not
`lost`), and that judgment is the stage-3 LLM gap.

## 7. Verification tooling

    benchmarks/eval_provenance.py   both columns, per category. Durable + resumable + progress.
                                    `--scope` runs the published per-conversation protocol.
    benchmarks/capture_golden.py    packed context per question: node ids IN PACKED ORDER.
                                    `--via-adapter` goes through the product path.
    benchmarks/diff_golden.py       IDENTICAL / REORDERED / DIFFERENT per question.
    benchmarks/capture_via_api.py   the same, through POST /api/v2/context with auth.
    bench_tmp/verify_ops.py         stage-by-stage check of evidence_ops on a known case.
    bench_tmp/packed_precision.py   what actually occupies the packed window.
    bench_tmp/analyze_mh.py         NOT_RETRIEVED vs RANKED_LOW vs PACKAGED per gold turn.

**Migration verification result:** 402-question reference captured pre-migration; post-migration
**391/397 byte-identical**, 3 correct-by-contract (abstain returns empty context, as v1 did),
3 timeouts during a Docker outage.

### The methodological lesson

`evidence_ops` measured **0.00** and turned out to be **three separate bugs**, each of which alone
made it a no-op: a rarity cut that discarded the right answer; a promotion applied before L3
(which recomputes from features); and L4 re-sorting blocks by its own score. **A number is only
evidence about an idea once the mechanism is shown to run.** Verify stage-by-stage before
trusting any negative result.

## 8. Deleted in this migration

`retrieve/planner.py` (1,474), `temporal_intent.py`, `decomposer.py`, `graph_algo.py`,
`index_retrievers.py` — **1,882 lines**. 67 benchmark files updated.

**`retrieve/` was NOT deleted** and must not be: it holds the answer path (`answer.py`), the
adapter, conversation memory (`memory.py`), ingestion helpers (`patterns.py`, `structured.py`),
ontology seeding (`seed*.py`), `trust.py`, `strata.py`, and `rerank.py` — which
`retrieval/l3_rerank/cross_encoder.py` imports.

## 9. Next, in order of evidence behind it

1. **`benchmarks/eval_answer.py` with a matched generator** (gpt-4o-mini ~$3-4, gpt-4.1-mini
   ~$8-10). Nothing else makes our number comparable to the published ones, and it is the only
   way to evaluate mechanisms our retrieval metric structurally cannot see.
2. **Better extraction model.** The noise is a 7B artifact — `"Joanna made cake cake"`,
   `nickname_used` holding 103 real names of 125. Noise doesn't waste slots, it BURIES truth
   (rank 5 vs rank 496 on the same question).
3. **Entity dedup by merging** (not `SAME_AS` aliasing). ~2.8 entity nodes per fact subject.
4. **The stage-3 LLM planner/validator** — the only untried idea with a live argument: an LLM can
   distinguish "both lost their jobs" from "both agree" where embeddings (0.525 vs 0.521) and
   rarity heuristics demonstrably cannot.

**Do not** raise `budget_tokens` to move a recall metric. The target must be met at the same
budget; more tokens buys the metric by spending context.
